## 2026-07-31 — 読みやすさと、使いやすさを測って直した（v1.4）

**新しい回は足していません。**「いま在るものの質を上げられるか」を、**推測ではなく測って**から直しました。

| 測ったこと | 結果 | 対応 |
| --- | --- | --- |
| **キーボードのフォーカス表示** | 実質見えない状態（1px） | **3pxの枠**を出すようにした |
| **指で押す場所の大きさ** | 10か所中**8か所が44px未満** | 5か所に削減（残りは本文中のリンク） |
| **小さすぎる文字** | 12px が混在 | 13px に底上げ |
| **図の枚数** | 後半6回のうち**4回が図ゼロ** | **図ゼロを解消**（不具合を追う／道具にする／保存先を変える に1枚ずつ） |
| **説明文の長さ** | 後半の解説が**前半の約2倍** | 長い順に**24か所を短く**（内容は削っていません） |
| **困ったときの助け** | 後半は前半の**3分の1**しかなかった | **22項目を追加**（APIの切り分け・SQLite・グラフ描画で詰まる所） |

## 2026-07-31 — 「動くものを、良くする」段階を追加（v1.3）

**ステップが 16 → 22 になりました。** 扱っていた不具合が「動かない」系ばかりで、**「動くけど遅い」が1つも無かった**のが理由です。案件で放置されて事故になるのは、こちらのほうなので。

| 追加 | 中身 |
| --- | --- |
| **17. 動くけど遅い、を直す** | 測る → 特定 → 直す → **もう一度測る**。推測で直さない |
| **18. 使い捨てをやめて、道具にする** | 毎回の `console.time` を、テスト付きの道具に。**そして人に共有する** |
| **19. 数字を、目に見えるようにする** | 計測結果をSVGの棒グラフに。**n²のカーブが目で見えます** |

| **22. 保存先を変えてみる（任意）** | SQLite を入れて、**壊して**、直す |

**読み物も5本増えました** — 工数の見積もり方／Claudeを分解してみる／AIに何を作ってもらうか／インフラの世界と、その入り口／そもそも Claude って何？

## 2026-07-31 — 逆算プランナーを、準備の本体に（v1.1）

**逆算プランナーが地図に載っておらず、サイドバーからしか行けませんでした。** 最終チェックのあと、計画を立てる段を通らずに参画相談へ直行していたので、地図の最後を **🎓 弱点を見つける → 🗓️ 計画を立てる → 🤝 相談する** の3行にしました。

あわせてプランナー自体を作り直しています。

- **到達度を6段階に**（12〜21のステップが存在しないことになっていました）＋**進捗から自動推定**
- **「すでにできること」を到達度から生成** — 固定文言だったため、**AIに嘘の前提を渡していました**
- **弱点を入れる欄を追加** — 最終チェックの「できていない項目をコピー」から、そのまま貼れます
- **「案件とのマッチ度を測る」ボタンを追加** — 研修で手を動かしたことの棚卸しと、案件の技術を突き合わせます
- **時間が足りないときに、足りないと言う** — 黙っていました
- **入力を保存** — 毎週作り直す前提なのに、毎回ゼロからでした
