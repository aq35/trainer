「多少なりとも考えさせる」という観点で全画面を見直しました。**足すより先に、数え方を直すことになりました。**

### 直したのは2か所です

**① 「動くけど遅い」5番 — 答えを手順に書いてしまっていました**

「20,000×20,000＝4億回」「20倍なら400倍」と、**いちばん大事な発見を、手順の中で先に言っていました**。

| 件数 | 時間 |
| --- | --- |
| 5,000 | 264ms |
| 10,000 | 1,085ms（**約4倍**） |
| 20,000 | 4,161ms（**さらに約4倍**） |

**件数は2倍。時間は4倍。**「2倍」と答える人がほとんどです。**そこで一度外すことが目的です。**

数字は Chromium で実測しました。20,000→40,000 も **×4.0** を確認しています。10万件の値だけは待ち時間が長すぎるので、**「計算上」と明記**しました。

もし成功してしまった人のために、受け皿も用意しました。**それは書き込み権限を渡してしまっているということ**で、直し方まで書いてあります。**安全な場所で気づけたなら、幸運です。**

**「動くけど遅い」7番にも、同じ形（直したあと5倍にしたら何倍？）を入れましたが、撤回しました。**

## 2026-08-03 — 「断る」練習が、ボタンを押すだけでした（v1.21）

前の版で、判断の演習に**固定の題材**を入れました。**同じ理由で残っていた最後の1つ**を直しました。

**5回目「まず、わざと断ってみます」**は、**正しい提案をボタンで断るだけ**でした。断る場所は分かりますが、**内容を理由に断った経験にはなりません**。

**直したこと**: **別の人のところに返ってきた提案**を1つ置きました。頼んだ言葉は同じ「最後に1行だけ足してください」です。

```
  こんにちは
- よろしくお願いします          ← 赤
+ よろしくお願いいたします        ← 緑
+ 今日は差分の読み方を覚えました    ← 緑
```

**緑が2行あります。** 頼んだのは最後の1行だけ。もう1つは、**もともとあった行を「より丁寧に」書き換えたもの**です。

<div class="checkpoint">
<strong>ここがいちばん怖いところです。</strong><br>
この変更は<b>親切</b>で、<b>実際に丁寧になっていて</b>、<b>悪意もありません</b>。<b>だから、通してしまいます。</b>
</div>

**「良くなっているかどうか」は、承認する理由になりません。** 基準は1つだけ——**頼んだことと一致しているか**。断り方の例文と、「なぜ良い変更でも断るのか」への答えも入れました。

**ここは4回目（差分を読む）の直後**です。赤と緑を覚えた次の回で、**その読み方が実際に効く場面**に当たります。

**「自分のところには余計な変更は来なかった」人向けの答えも用意しました。** それが普通です。**100回のうち99回は問題なく、残りの1回を見逃したときだけ事故になります。**

## 2026-08-03 — 「AIの出力を判断する」演習が、AI任せでした（v1.20）

この教材がいちばん大きく約束しているのは、**「書くのはAI、決めるのは自分」**です。では、**決める練習は何回あるのか**を数えました。

<div class="checkpoint">
<strong>「AIが返してきたものを、条件と照らして判断する」演習は、22回のうち 2回だけでした。</strong><br>
しかも<b>その2回とも、成否がAIの出力しだい</b>です。
</div>

**何が問題か。** 「返ってきたコードを5つの条件と照らしてください」と書いてあっても、**AIがちゃんとしたコードを返せば、学習者は「全部OK」と言って終わります。** 欠けているものを見つける経験は、**一度もできません**。

**この教材は、同じ問題をレビューの回で一度解いています。** レビューの回は、**問題を7つ植えたブランチ**を用意してあります。だから**必ず見つかります**。AI任せにしていません。**その型を、判断の演習にも入れました。**

### ① 道具の回 — 「AIはこう返してきました」を固定で置きました

読むだけの画面だったところに、**実際にAIが返しがちなコード**を1つ置き、**5つの条件と照らして、欠けている2つを探してもらいます**。

- **①「戻り値をそのまま返す」** — <code>return fn()</code> ではなく <code>fn()</code> になっている。**包むだけで壊れない、という前提が崩れます**
- **⑤「例外が出ても記録は残る」** — <code>try … finally</code> が無いので、**落ちたときだけ記録が消えます**

**どちらも、動かしても気づきません。** 戻り値を使わなければ①は表に出ず、⑤は**落ちたときにしか**出ません。**だから条件と照らすしかない**——それを、答えのある形で体験できます。

### ② 仕事の回 — 「正しい指摘」と「いま直す指摘」は別物です

AIのレビューを受けたあと、**実際に来がちな指摘3つ**を固定で置き、**「いま直す／別のチケットにする／断る」**に振り分けてもらいます。**3つとも正しい指摘ですが、扱いは3つとも違います。**

| 指摘 | 正解 | なぜ |
| --- | --- | --- |
| 別の場所のエラー処理が無い | **別のチケット** | 正しいが、**あなたが触っていない行**。1行のPRに混ぜると、レビューする人が事故ります |
| 定数をやめて直接書いたほうが読みやすい | **断る** | 好みの話で、**いまの作りをわざわざ壊します**。断るのは失礼ではありません |
| なぜ壊れていたのかがPRに書かれていない | **いま直す** | **このPRの中の話**で、しかも**説明を足すだけ**。いちばん安く、いちばん効きます |

**「正しさは、いま直す理由になりません。」** これを言葉にできる人が、現場で信用されます。

**どちらも答えは折りたたみの中**に入れました。**先に自分で決めてから開いてください。**

## 2026-08-03 — 「終わりが来ない演習」と、開かない相談パネル（v1.17）

**「演習として微妙なのは？」**という問いを受けて、**壊れてはいないが、演習としては弱い**画面を探しました。3つの型に分けて、全部直しました。

### ① 1画面のはずが、終わりが来ない

| 画面 | 何が起きていたか |
| --- | --- |
| **AI-DLC 6.「1つずつ作って commit」** | 手順の最後が「**これを繰り返します**」。予約アプリを**全部作りきる**まで終わらない画面でした（数時間〜数日）。「1つ目で先に進んでよい」とは、**折りたたみの中にしか書いていません**でした |
| **DB 5.「小さく作る」** | ①〜④の4段階が1画面。しかも**④はブラウザからDBを直接読めないので、そもそもできません**。「③で止めてよい」は、これも折りたたみの中でした |

**直したこと**: どちらも「**この画面はここまでで合格**」を、**手順の中に**書きました。成功条件も、実際に確かめられる形に書き替えました（DBは「読み書きできる状態」→「**12件のうち1件と、終わっていないものだけが表示される**」）。

### ② 相手がいないと、終われない

**道具 8.「作ったことを、誰かに伝えます」**は、行き先が「**チームがあればチャット**」か「**Discussions**（まだ開けていません）」の2つだけでした。**一人で学んでいる人は、ここで終われません。**

**直したこと**: **必ずできること**を第一手順にしました——**いま出したプルリクエストの説明に3行足す**。これは相手を探す必要がなく、あとで差分を見る人が必ず読む場所です。相手がいる人は、そのあと同じ3行を送る、という順にしました。

### ③ 正解がどこにもなく、ズレても気づけない

**AI-DLC だけは、練習リポジトリを使いません**（新しく `reserve-app` を作ります）。つまり**答え合わせの相手がいません**。とくに `requirements.md` は、**書けたのかどうかを自分で判定できませんでした**。

**直したこと**: 「これでいいのか分からない」に、**実物の見本**を丸ごと入れました。そして判定を2つだけに絞りました——**①「やらないこと」が3つ以上ある ②読んだ人が最初の1画面を作れる**。長さも形式も問いません。

### ついでに見つかった、こちらの不具合

<div class="checkpoint">
<strong>4つの回で、「うまくいきません」のパネルが開きませんでした。</strong><br>
対象: <b>API・グラフ・速さ・道具</b>の4回（<b>全ステップ</b>）
</div>
