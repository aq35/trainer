# 案件に入る前の最終チェック

<div class="lead">
ここまでおつかれさまでした。最後に、<b>自分がどこまで来たか</b>を確かめます。<br>
できていない項目があっても、<b>まったく問題ありません</b>。戻る場所へのリンクを付けてあります。
</div>

<div class="note">
チェックはこのブラウザに保存されます。<b>全部にチェックが付いていなくても、案件に入れないという意味ではありません。</b>「どこが弱いか」を、自分と担当者が把握するための表です。
</div>

## 1. 道具が使える

- [ ] VS Code を開いて、フォルダを開ける
- [ ] ターミナルを出して、コマンドを打てる（[ターミナル入門](step0-terminal.md)）
- [ ] Claude Code に話しかけて、返事が返ってくる（[環境構築](setup.html ':ignore target=_blank')）
- [ ] <span>目的のファイルを `Ctrl+P` と全文検索で探せる（[自分のテーマで回す](theme.html ':ignore target=_blank')）</span>

## 2. 記録が残せる

- [ ] `git status` / `add` / `commit` / `log` / `restore` の意味が言える（[git の基本](git.html ':ignore target=_blank')）
- [ ] 壊しても、動いていた地点に戻せる
- [ ] GitHub に上げられる（[GitHubに上げる](github.html ':ignore target=_blank')）
- [ ] ブランチを作って、本線に取り込める（[ブランチと安全な進め方](branch.html ':ignore target=_blank')）
- [ ] コンフリクトが起きても、自分で直せる

## 3. 他人と仕事ができる

- [ ] 他人のリポジトリを `git clone` して手元で動かせる（[仕事の一周](work.html ':ignore target=_blank')）
- [ ] 既存のコードから、直す場所を見つけられる
- [ ] エラーが出ない不具合を、切り分けて特定できる
- [ ] **あいまいな依頼に、着手前に質問できる**
- [ ] プルリクエストに、他人が読んで分かる説明を書ける
- [ ] 自動チェックの指摘を読んで直せる
- [ ] 他人の変更とのコンフリクトを解決できる
- [ ] 作業前に `git pull` する習慣がある
- [ ] **自分でテストを書ける**（[仕事の一周](work.html ':ignore target=_blank')）
- [ ] **テストに守られて、動きを変えずにコードを書き直せる**
- [ ] 工夫したことを、チームに共有できる（[AIに何を作ってもらうか](what-to-build.md)）

## 4. 人と組んで進められる

- [ ] **他人の差分を、観点を持って読める**（[レビューする側になる](review.html ':ignore target=_blank')）
- [ ] 指摘に優先順位を付けられる（戻せない → 壊れる → 後で困る → 好み）
- [ ] **相手が直しやすい書き方**で指摘できる。良い点も伝えられる
- [ ] 取り込むべきでないものを、理由を添えて止められる
- [ ] **曖昧な不具合報告から、自分で再現できる**（[曖昧な報告から不具合を追う](bug.html ':ignore target=_blank')）
- [ ] 1つずつ変えて、原因を切り分けられる
- [ ] 技術を知らない人に、伝わる言葉で結果を返せる
- [ ] **知らない大きさのコードに、読まずに入れる**（[大きなコードに初日で入る](onboard.html ':ignore target=_blank')）
- [ ] 見えている文字で全文検索して、目的の場所にたどり着ける
- [ ] **15分で止まって、人に聞ける**（[詰まったときに、人を頼る](ask.html ':ignore target=_blank')）
- [ ] 相談文に4つ（目的・手順・起きたこと・試したこと）を書ける
- [ ] エラーを要約せず、そのまま貼れる
- [ ] **遅れそう・できない・間違えた**を、早く伝えられる

## 5. AIと組んで進められる

- [ ] 差分を読んで、OKか断るかを自分で決められる（[差分を読む](diff.html ':ignore target=_blank')）
- [ ] 範囲を区切って頼める（「@このファイルだけ」「1行だけ」）
- [ ] `CLAUDE.md` に前提を書いて、毎回説明せずに済ませられる
- [ ] おかしくなったら `/clear` で立て直せる（[自分のテーマで回す](theme.html ':ignore target=_blank')）
- [ ] **AIに貼ってはいけないもの**が言える（[AIと一緒に直す](ai.html ':ignore target=_blank')）
- [ ] **Claude と Claude Code の違い**が言える（[そもそも Claude って何？](what-is-claude.md)）
- [ ] **毎回頼む仕事**と**一度作れば残る道具**を、区別して頼める

## 6. 自分で作れる

- [ ] HTMLを書いて、ブラウザで動かせる（[はじめてのプログラム](code.html ':ignore target=_blank')）
- [ ] エラーが出たとき、開発者ツールの Console を見に行ける
- [ ] 自分で決めたテーマを、1週間ぶん進められた（[自分のテーマで回す](theme.html ':ignore target=_blank')）
- [ ] **あいまいな依頼から、要件を聞き出して形にできる**（[AIと回す開発の一周](ai-dlc.html ':ignore target=_blank')）
- [ ] 作る前に「できたと言える条件」を決められる
- [ ] 追加の要望を、受けるか・後回しか・断るか判断できる
- [ ] 詰まったとき、15分で切り上げて人に聞ける

## 案件に入ると、ここから何が変わるか

<div class="qa">
<div class="q">研修と、いちばん違うのはどこですか？</div>
<div class="a"><b>「自分以外の人がいる」ことです。</b>コードは他人が読み、他人が直します。だから、動くだけでは足りず「読める・説明できる」ことが求められます。技術の難易度より、この違いのほうが大きいです。</div>
</div>

**① レビューを受けます**
自分の変更は、そのまま本線には入りません。プルリクエストを出して、**他の人に読んでもらってから**取り込まれます。[仕事の一周](work.html ':ignore target=_blank')で、機械（自動チェック）とAIからの指摘は経験しました。そして[レビューする側になる](review.html ':ignore target=_blank')で、**指摘する側**も一度やっています。**受ける側と、する側の両方を知っている**——それが、この研修を終えたあなたの状態です。

<div class="note">
<b>指摘は、あなたへの評価ではありません。</b>コードに対する意見です。ベテランでも毎回指摘されます。「直してください」と言われたら、直せばいいだけです。
</div>

**② 毎日 `pull` します**
他の人が変更を入れるので、**作業を始める前に最新を取り込む**のが日課になります。[仕事の一周](work.html ':ignore target=_blank')の2つ目のチケットから、この習慣を始めています。取り込まずに進めると、コンフリクトが大きくなります。

**③ ルールがあります**
コミットメッセージの書き方、ブランチの名前、AIの使用範囲。**チームごとに違います。** 分からないまま進めず、初日に確認してください。

<div class="trivia">
<div class="ct">先に知っておくと楽なこと</div>
最初の1〜2週間は、<b>「環境が動かない」「どこに何があるか分からない」</b>で大半の時間が過ぎます。これは能力の問題ではなく、<b>全員が通る道</b>です。研修でやった「15分で聞く」を、そのまま持ち込んでください。
</div>

## 弱いところが見つかったら

戻ってやり直すのがいちばん早いです。**同じナビをもう一度通しても、進捗は上書きされるだけで壊れません。**

- コマンドが不安 → [⌨️ コマンド練習](drill.html ':ignore target=_blank')で反復できます
- 言葉が不安 → [用語集](glossary.md)
- 全体を見直したい → [トップページ](/)
