## きっかけは、使っていた道具が使えなくなったこと

Git は、**Linux カーネル**（世界中の人が変更を持ち寄って作っている、大きなソフトウェア）を開発するために作られました。

| 年 | 何があったか（Pro Git 1.2 より） |
| --- | --- |
| 1991〜2002 | 変更は、パッチ（差分のファイル）やアーカイブとして、人から人へ回されていた |
| 2002 | BitKeeper という、企業が作った分散型のバージョン管理システムを使い始めた |
| 2005 | 開発者の集まりと BitKeeper の会社との協力関係が崩れ、**無償で使える状態が取り消された** |
| 2005 | Linux の作者 Linus Torvalds らが、BitKeeper で学んだことをもとに、**自分たちの道具を作り始めた**。それが Git |

## 最初から決めていた目標

Pro Git 1.2 には、新しい道具の目標が5つ書かれています。

1. **スピード**
2. **シンプルな設計**
3. **ノンリニア開発（数千の並列ブランチ）への強力なサポート**
4. **完全な分散**
5. **Linux カーネルのような大規模プロジェクトを、効率的に扱える**

このうち、第2回ですでに体験したのが「**完全な分散**」です。

## 「完全な分散」とは

Pro Git 1.1 では、Git のような分散型では、**クローンが「全データの完全バックアップ」になる**と説明しています。

これは他人事ではありません。第2回であなたがクローンした trainer フォルダにも、**この教材の履歴が、全部入っています**。だから `git log` は、ネットにつながっていなくても動きます。

## コミットの番号（ハッシュ）は、中身から計算される

`git log --oneline` の左に出る英数字は、コミットを見分けるための番号（**ハッシュ**）の先頭の部分です。

Pro Git 1.3「Gitは完全性を持つ」によると、Git はすべてのものについて、**格納する前にチェックサム（中身から計算した値）を取ります**。そのため、**Git が気づかないうちに中身が変わる、ということが起きません**。

第3回で、「番号はあなたの画面では違います（名前・日時・中身などから計算されるため）」と書いたのは、このためです。

## 名前の由来

Git 本体の README によると、名前は Linus Torvalds が最初の版を書いたときに付けたもので、**気分によって、いくつかの意味に読める**と説明されています。たとえば:

- 発音できて、UNIX のよくあるコマンドと重ならない、**ただの3文字**
- 俗語の「**stupid**（まぬけ）」「**contemptible and despicable**（卑しい）」「**simple**（単純）」（辞書から好きなものを選んで、と書かれています）
- うまく動いてくれたときは「**global information tracker**」

真面目な由来ではなく、**冗談まじりの説明**です。

## まとめ

- Git は、2005年に**使っていた道具が使えなくなった**ことをきっかけに、Linux の開発者たちが作った
- 目標は **スピード・シンプル・ブランチ・完全な分散・大規模**
- **クローンは、履歴の完全なコピー**。だから手元だけで作業できる
- コミットの番号は**中身から計算される**。だから中身が変われば、Git は気づく
